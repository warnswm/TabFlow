# TabFlow

Chrome-расширение — менеджер вкладок. Гибрид OneTab (сбросить вкладки одним кликом, освободить память) и Toby (пространства, группы плитками), плюс очередь видео «на потом».

**Слоган:** «Всё на виду. Ничего в памяти.» / _Everything in sight. Nothing in memory._

## Background (этап 2)

`src/lib/background/`: `index.ts` (`createBackground` — очередь команд и событий) · `mirror.ts` (зеркало) · `group-actions.ts` (усыпить / убрать / вернуть, изменить, открыть ссылку) · `trash-actions.ts` (удалить в корзину / восстановить) · `collapse.ts` (свернуть всё) · `move-tab.ts` (перенос ссылки) · `tab-rules.ts` (исключения, дубликаты) · `serial-queue.ts`. Протокол команд — `src/lib/messages.ts`; тексты результатов — `src/lib/command-messages.ts`; заглушки — `src/lib/placeholder.ts` + `entrypoints/lazy/`.

- **Страницы ↔ background:** страницы читают Dexie напрямую (`useLiveQuery` из `src/lib/use-live-query.ts`), а всё, что трогает вкладки Chrome, — только командами (`sendCommand`). Команды и события Chrome выполняются **по одной** в общей очереди — иначе события от собственных действий плодят дубли в зеркале.
- **Сначала БД, потом закрыть вкладки.** Окно никогда не остаётся пустым — перед закрытием последних вкладок открывается главная TabFlow.
- **Свернуть всё** (текущее окно): каждая нативная группа убирается отдельно (название и цвет сохраняются), вкладки вне групп — в одну новую группу «16 окт, 23:40» во «Входящих». Закреплённые и служебные (`chrome://`, `about:`, страницы расширений и т.п.; сохраняются только `http`, `https`, `file`) остаются открытыми.
- **Дубликаты** — только внутри одной сохраняемой группы, адрес сравнивается без `#якоря`.
- **Зеркало:** события — лишь подсказка, группа каждый раз сверяется с Chrome целиком. Закрыли вкладку в Chrome → в корзину; вынесли из группы (открыта) → забывается; закрыли группу или окно → группа становится убранной со всеми ссылками; распустили группу → забывается; все вкладки выгружены → «спит». **Ссылка никогда не меняется и не удаляется из-за того, что вкладка показывает служебный адрес** (`about:blank`).
- **Новая сессия браузера** определяется меткой в `storage.session` (Chrome чистит его при перезапуске): старые id отвязываются, группы сопоставляются по названию, цвету и адресам; заодно `trash.purgeExpired()`.
- **Сохранённые группы Chrome** (`revive.ts`): Chrome держит каждую группу в своих сохранённых (панель закладок, «закрытые»), и после того как TabFlow её убрал. Открыли её из Chrome → новая нативная группа сопоставляется с **убранной** группой TabFlow тем же `findMatch` (название + цвет + не меньше половины адресов) и становится ею, а не дубликатом; ссылки, которых нет в копии Chrome (сохранены в группу, пока она была убрана), открываются в ней заглушками. Работает и на событиях (`reviveFromChrome` перед зеркалом), и при пробуждении service worker (`reconcileAll`: `reopenMissing` для возвращённых убранных групп). API сохранённых групп у расширений нет: закрытые группы Chrome нельзя ни открыть, ни удалить, ни переставить — поэтому «Вернуть» в TabFlow создаёт в Chrome новую сохранённую группу (старая закрытая остаётся; проверить вручную).
- **Порядок групп на панели = порядок TabFlow** (`arrange.ts`, `arrangeGroups`): пространства (как в сайдбаре, «Входящие» первые), затем плитки. Группы окна встают подряд с места самой левой; вкладки вне групп между ними сдвигаются вправо; если порядок верный — ничего не двигается. Применяется после «Вернуть», после возврата из Chrome и командой `arrangeGroups` со страницы (перетаскивание плиток и пространств, перенос в другое пространство). **Обратно** (`followStrip`): пользователь перетащил группу на панели Chrome (`tabGroups.onMoved` → отдельное событие `groupMoved`, не `groupChanged`) → в каждом пространстве открытые группы этого окна занимают свои же места среди плиток в порядке панели; убранные группы и группы других окон стоят на месте (не переписываются). Переставляется минимум плиток (`placeMoves`: самый длинный уже верный ряд остаётся, остальные — `groups.place` за новым левым соседом). Порядок пространств панель не меняет: группа, перетащенная к группам чужого пространства, сдвигается только среди своих. Свои перестановки TabFlow встречной не вызывают: после `arrangeGroups` порядок внутри пространства уже совпадает — записи в БД нет (тест со шпионом на `place`). Только `groupMoved`, а не любые `tabUpdated`: иначе событие вкладки между записью плиток страницей и командой `arrangeGroups` вернуло бы старый порядок. Что Chrome шлёт `onMoved` при перетаскивании группы мышью — проверить вручную. В тестах — `FakeTabsApi.moveGroup` (шлёт `groupMoved`), `api.sleepWorker()` + `t.wakeWorker()`.
- **Вернуть:** первая вкладка открывается и сразу становится нативной группой, остальные открываются параллельно и встают в неё. Два способа (`RestoreMode`, выбор — страница настроек): `placeholder` (по умолчанию) — вкладка открывает лёгкую страницу `lazy.html` с настоящим названием и иконкой (иконка из кэша Chrome `_favicon`), выгружается и переходит на сайт при открытии; `background` — открываются сами сайты и выгружаются в фоне. `browser-api` отдаёт за заглушкой настоящий адрес, так что зеркало и «Убрать» её не замечают.
- **Заглушки — страницы самого TabFlow** (`placeholder-icons.ts`), поэтому Chrome обращается с ними иначе, чем с сайтами (проверено вручную в Chrome 155): (1) после перезапуска Chrome они возвращаются невыгруженными **без иконки** — в новой сессии фоновые заглушки перезагружаются (`TabsApi.reloadTab`, сайты не грузятся) и снова выгружаются, когда иконка применена; вкладки, которые Chrome восстанавливает позже, ловятся по `tabCreated` ещё 60 с (кроме открытых командами TabFlow); (2) при **перезагрузке или обновлении расширения Chrome закрывает все его страницы** (заглушки, главную) — при старте в новой сессии `reconcileAll(…, reopenMissing)` открывает пропавшие ссылки открытых групп заглушками на их местах (`reopenMissingLinks`), а не отправляет в корзину. Ссылка из корзины в группу на панели тоже возвращается заглушкой (или сайтом в режиме `background`); в корзине ссылки собраны по группам с «Восстановить все». В тестах — `FakeTabsApi.reloadExtension()` / `t.reloadExtension()`.
- Память в МБ не показываем: в стабильном Chrome нет API памяти вкладки (`chrome.processes` — только Dev-канал). Пишем количество вкладок.
- Разрешения: `tabs`, `tabGroups`, `storage`, `favicon`, `contextMenus`, `sidePanel`, `scripting`, `declarativeNetRequestWithHostAccess`, `alarms` (без предупреждения при установке; `commands` и бейдж разрешений не требуют) + `optional_host_permissions: *://*/*` — доступ к сайтам только по запросу (этап 6).

## Главная (этап 3)

`src/entrypoints/app/`: `App.tsx` (сайдбар + экран по `#hash`) · `components/` (Sidebar, SpaceView, GroupTile, GroupMenu, GroupDialogs, SpaceDialogs, TrashView, Toaster) · `commands.ts` (`runCommand` — команда + тост + «Отменить») · `store.ts` (Zustand: тост, способ возврата) · `ui.ts` (классы кнопок, меню, диалогов) · `hooks.ts` (`useRoute`, `useNow`). Чистая логика с тестами — `src/lib/app/`: `overview.ts`, `trash-view.ts`, `undo.ts`, `route.ts`, `time-format.ts`, `youtube.ts`.

- **Экраны:** `#/space/<id>` (без id — «Входящие»), `#/trash`. Роутер не нужен.
- **Плитка:** превью 16:9 — мозаика 2×2 из первых ссылок: обложка YouTube по ID видео (`i.ytimg.com` — единственный запрос в сеть) или иконка из кэша Chrome (`faviconUrl` → `_favicon`) + домен. Не больше 4 плиток в ряд, на узком окне меньше (мин. 260 px). Состояние не только цветом: спит — превью 50 % + значок луны + «Разбудить»; убрана — без фона, пунктир `border-control`, значок архива + «Вернуть». Подпись «Уснула / Убрана N назад» — поле `TabGroup.stateChangedAt` (без индекса, версия схемы не менялась).
- **Кто пишет в БД:** всё, что трогает группы и вкладки Chrome или удаляет, — командами: `editGroup` (меняет и группу в Chrome — иначе зеркало перезапишет название), `deleteGroup`, `deleteSpace`, `deleteTab`, `restoreDeleted`, `openTab`. Только БД (страница пишет сама): создать / переименовать пространство, перенести группу в другое пространство.
- **Удаление открытой группы:** сначала она убирается (`stowInDb`) и уходит в корзину, потом вкладки закрываются — зеркало не видит удалённую группу с открытыми вкладками. Пространство — так же для всех его открытых групп, один `deletedAt` на всё. Последняя ссылка группы удаляется вместе с группой. «Входящие» не удаляются (`space-protected`).
- **Undo** (`lib/app/undo.ts`) — новая команда: убрать / свернуть всё → `restoreGroup` для `CommandResult.closedGroupIds`; удалить → `restoreDeleted` с `reopenGroupIds` (закрытые удалением группы снова открываются). Усыпить — без отмены («Разбудить»). Восстановленная ссылка в группе на панели сразу открывается в ней — иначе зеркало вернёт её в корзину.
- **Корзина:** удалённое вместе показывается одной строкой (пространство с группами, группа со ссылками); отдельные ссылки — «из «Группа»», до 200 строк.
- **Способ возврата** (`RestoreMode`) и **число на значке** (`BadgeMode`, этап 6) — на странице настроек (`#/settings`, ссылка «Настройки» внизу сайдбара), хранятся в `storage.local` (`lib/settings.ts`).
- Тесты компонентов React пока не пишем (нет Testing Library) — логика вынесена в `src/lib/app/` и команды background.

## Поиск, палитра, drag & drop (этап 4)

Логика — `src/lib/app/`: `search.ts` (индекс MiniSearch, `highlight`) · `filters.ts` (чипы) · `palette.ts` (содержимое палитры) · `reorder.ts` (порядок сразу после броска). UI — `components/CommandPalette.tsx`, `Highlighted.tsx`, `dnd.ts` (сенсоры, цель броска, озвучка по-русски).

- **Поиск:** индекс в памяти из overview (названия групп; заголовок, домен и путь ссылок), пересобирается при каждом изменении БД. Начало слова, опечатка в словах длиннее 3 букв, регистр и «ё» не важны, все слова запроса обязательны. Поле в шапке фильтрует плитки **текущего** пространства на месте (подсветка в названии, «N ссылок совпадают», подсветка в «Ссылках»); палитра ищет **во всех**.
- **Чипы** «Все / Активные / Спят / Убраны» — счётчики по текущему пространству с учётом поиска. Поиск и чип сбрасываются при смене экрана (`resetFilters` в store).
- **Палитра Ctrl+K** (`event.code === 'KeyK'` — работает и в русской раскладке; только на главной, глобальные хоткеи — этап 5): «Группы» (Enter — перейти к плитке: пространство, прокрутка, обводка 2 с), «Вкладки» (Enter — `openTab`), «Действия» (свернуть всё, перейти в пространство, корзина, новое пространство + усыпить / убрать / разбудить / вернуть лучшую найденную группу).
- **Drag & drop** (один `DndContext` в `App`, обработчики — `useDndMonitor` в `SpaceView` и `Sidebar`): плитка — за любое место (6 px — ещё клик) или за ручку с клавиатуры (Пробел — взять / поставить, Enter оставлен ссылкам, Esc — отмена); плитку можно бросить на пространство в сайдбаре (тост с «Отменить»); пространства сортируются, «Входящие» всегда первые; пока включён поиск или чип — перетаскивание выключено. Ключ `order` — `placeAt` (`db/order.ts`): середина между соседями, а если места нет — весь список переписывается ровными ключами (`groups.place`, `spaces.place`, `tabs.place`). Плитки и пространства — только БД (страница пишет сама).
- **Ссылки** переставляются в «Ссылках» за ручку ⠿ и переносятся в другую группу через «⋯ → Перенести в группу ▸» — командой `moveTab`: сначала БД, потом панель Chrome. Обе группы на панели — вкладка переезжает в другую нативную группу (`TabsApi.moveTab` = `chrome.tabs.move`; другое окно — сначала туда), на место ссылки; в убранную — вкладка закрывается; из убранной в открытую — ссылка открывается вкладкой этой группы; спящая группа остаётся спящей. Последняя ссылка оставляет пустую группу в корзине; Undo: `restoreDeleted` → `moveTab` обратно → `restoreGroup` (если группа была на панели). Порядок открытой группы потом всё равно сверяет зеркало по Chrome.

## Popup, меню, хоткеи, бейдж (этап 5)

Команды — `src/lib/background/quick-actions.ts`; чистая логика — `src/lib/summary.ts` (сводка popup, бейдж, `currentTarget`), `src/lib/menus.ts` (`buildMenu`, `menuCommand`), `src/lib/hotkeys.ts` (`HOTKEYS` для манифеста — `wxt.config.ts` импортирует их отсюда, поэтому в файле только `import type`); бейдж и меню применяет `background/ui-refresh.ts`. Chrome-вызовы — `ExtensionUi` в `browser-api.ts` (`setBadge`, `setMenu`), `onMenuClick`, `onHotkey`, `getHotkey`, `getOpenTabsInfo`; в тестах — `FakeExtensionUi` (`t.ui`).

- **«Убрать в TabFlow» (`stowCurrent`)**: вкладка в группе → убирается вся группа; вне группы → одна вкладка в **группу дня** во «Входящих» «17 окт · отложено» (ищется по названию, нет — создаётся убранной). Туда же «Сохранить ссылку». Закреплённые и служебные — `tab-not-saveable`, группа дня при этом не создаётся. Повтор адреса в группе не сохраняется (вкладка всё равно закрывается).
- **«В группу ▸»** (`saveToGroup` / `saveLink` с `groupId`): 10 последних изменённых групп (`updatedAt`), «Название · Пространство». Вкладка-ссылка другой группы переносится как `moveTab`; вкладка вне групп — в убранную группу закрывается, в группу на панели переезжает в её нативную группу (`moveIntoGroup`). Ссылка в группу на панели сразу открывается её вкладкой (`openInGroup`) — иначе зеркало отправит её в корзину.
- **«Убрать выделенные» (`stowSelected`)** — только в popup, строка видна при 2+ выделенных вкладках (Ctrl+клик / Shift+клик на панели; `BrowserTab.highlighted`, активная вкладка всегда выделена, активация сбрасывает выделение — так же в `FakeTabsApi`, помощник `userSelectTabs`). Выделенные вкладки текущего окна → новая убранная группа во «Входящих» с названием как у «Свернуть всё»; ссылки других групп переезжают в неё, опустевшая группа уходит в корзину (как `moveTab`). Хоткей и меню выделение не учитывают.
- **«Усыпить неактивные»** — все активные группы, кроме групп активных вкладок **всех** окон (`isSleepable`, одно правило для popup и background).
- **Меню:** на странице (`page`) и ссылке (`link`) — только для `http`, `https`, `file` (`documentUrlPatterns` / `targetUrlPatterns`); на иконке (`action`) — «Свернуть всё», «Открыть TabFlow». Меню на самой вкладке (правый клик по заголовку вкладки) расширения в Chrome дополнять не могут (контекст `tab` — только Firefox); «ссылка» — ссылка внутри страницы. У меню и хоткеев нет страницы для тоста: результат виден по вкладкам, ошибки — только в лог (`console.info`).
- **Хоткеи** (Chrome принимает ≤ 4 предложенных): `Ctrl+Shift+S` — свернуть всё, `Alt+Shift+S` — убрать текущее, `Alt+Shift+Z` — усыпить текущую группу, `Alt+Shift+M` — открыть главную (или перейти на открытую). Popup (`_execute_action`) — без сочетания по умолчанию. **При перезагрузке уже установленного расширения Chrome назначил не все новые сочетания** (`Alt+Shift+Z`, `Alt+Shift+M` автор назначил вручную) — после изменения `commands` сверяться с `chrome://extensions/shortcuts`; kbd в popup читает реальное сочетание (`commands.getAll`).
- **Бейдж** — с этапа 6 по выбору (см. «Очередь видео»), по умолчанию видео на сегодня (0 — пусто, >99 — «99+»), фон `#2DD4BF`, текст `#04201C`. Бейдж и меню пересчитываются после каждой работы в очереди background (одним заданием после серии) и применяются, только если изменились. Страница сама пишет в БД лишь порядок и пространства — подписи «· Пространство» в меню обновятся со следующим событием.
- **Popup:** сводка «вкладок открыто · групп спят N/M · убрано в TabFlow» (памяти в МБ нет — см. выше), «Свернуть всё», быстрые действия для текущей вкладки (`currentTarget`), «Открыть TabFlow» — командой `openApp`. Undo в popup нет — убранное возвращается с главной («Вернуть»).

## Очередь видео и боковая панель (этап 6)

Логика — `src/lib/queue/`: `plan.ts` («На сегодня», подбор под время, сортировка, форматы) · `video-url.ts` (`videoKey`, сайт, чистка заголовка) · `site-access.ts` (шаблоны доступа к сайтам) · `video-page.ts` (правила content script). Команды — `background/queue-actions.ts`; бейдж — `badge()` в `summary.ts`. UI — `entrypoints/sidepanel/` (`QueuePanel`, `GroupsPanel`; тост, `runCommand` и классы — общие с главной), `app/components/QueueStrip.tsx` и `VideoThumb.tsx`; content script — `entrypoints/video.content.ts`.

- **Добавить в очередь** (`queueTab` — меню страницы, popup «Видео в очередь», панель «Добавить текущую вкладку», хоткей `queue-current` без клавиши; `queueLink` — меню ссылки): **вкладка остаётся открытой**, ссылка группы TabFlow остаётся в группе. Только `http`, `https`, `file` (закреплённые можно) — иначе `page-not-queueable`. Одно видео — один ключ `videoKey`: id YouTube или адрес без `#якоря` и `t`/`start` — повтор не добавляется («уже в очереди — #2»).
- **Все изменения очереди — командами** (`openVideo`, `moveVideo`, `setWatched`, `removeVideo`, `restoreVideo`), чтобы бейдж пересчитывался в очереди background. `openVideo`: вкладка с этим видео уже открыта → переход к ней, иначе новая вкладка в конце текущего окна (вне групп). Удалённое — в корзину 30 дней (на странице корзины не показывается, отмена — тостом). Undo: добавить → `removeVideo`; удалить → `restoreVideo`; «Просмотрено» → назад на старое место (`wasPriority` + `moveVideo`).
- **«На сегодня»** — первые 3 видео очереди (`TODAY_COUNT`), время — остаток (длительность − позиция) у тех, где длительность известна. **Чипы 10 / 20 / 40 / 1 ч+** — отдельная подсказка, не запоминаются: по приоритету берётся всё, что помещается («За 20 мин: #1 и #3 · 19 мин»), такие строки подсвечены; «1 ч+» — если ничего не влезло в час, берётся первое видео с известной длительностью. Видео без длительности в подбор не попадают («—» на обложке).
- **Боковая панель** (`chrome.sidePanel`, Chrome 114+) открывается только прямо в клике или хоткее (`openSidePanel(windowId)` без `await` перед ним): popup «Открыть очередь», «Вся очередь · N» на главной, «Открыть очередь» в меню значка, хоткей `open-queue` без клавиши; ещё — значок боковой панели Chrome. Сортировка «Сначала короткие» — только вид, перетаскивание тогда выключено. «Просмотрено» — свёрнутый список последних 20 с «Вернуть в очередь».
- **Время везде — остаток** (длительность − позиция), поэтому у начатого видео на обложке «29:12 / 37:05» (`durationLabel`; на маленькой обложке панели часовые — только длительность), полоска просмотра — красная, как у YouTube (токен `video-progress` `#FF0033`: бирюзовая терялась на обложках), процент в строке стоит перед каналом.
- **Полоса «Очередь» на главной** (под плитками, скрыта при поиске и чипе) — один ряд первых видео: карточек столько, сколько влезает в ширину (не уже 240 px, `cardsInRow`, пересчёт по `ResizeObserver`); «Вся очередь · N» открывает боковую панель.
- **Доступ к сайтам по запросу**: при установке доступа нет; при добавлении видео Chrome спрашивает доступ к его сайту (`requestSiteAccess` — первым же вызовом в клике; разрешённый сайт не спрашивается). Отказали — видео всё равно в очереди, в панели у него «Доступ» и пункт «Разрешить доступ к сайту». Из меню и хоткея (service worker) запрос может не сработать — тогда остаётся этот путь. Отозвать — `chrome://extensions` → TabFlow → «Доступ к сайтам».
- **Content script** регистрируется в рантайме на разрешённых сайтах (`syncVideoScript`: `scripting.registerContentScripts`, все фреймы, переживает перезапуск) и сразу запускается в уже открытых вкладках новых сайтов (`injectVideoScript` на `permissions.onAdded`). Видео страницы — самый крупный `<video>` ≥ 200×100; реклама YouTube (`.ad-showing`) и прямые эфиры (длительность ∞) не считаются. Отчёт `videoProgress` — при загрузке видео, раз в 10 с при просмотре, на паузе, перемотке, уходе со страницы и по запросу background (`requestVideoReport` после добавления). Background принимает `videoProgress` **только от content script** (страницу берёт из вкладки отправителя), а content script может слать **только** `videoProgress` (`MessageOrigin`). Обновляется только видео из очереди: длительность, канал и заголовок (если был адрес), позиция; последние 5 % (≤ 30 с) или `ended` → «Просмотрено»; заново загруженное видео в начале получает `seekToSec` — продолжение с сохранённого места.
- **Встроенные плееры** (видео в iframe другого сайта — Vimeo, Kinescope и т.п.): content script страницы сообщает их адреса (`playerOrigins`), «Разрешить доступ» просит сайт и плеер одним окном. Некоторые плееры длительность не отдают — тогда «—»; проверяется только вручную на живом сайте.
- **Бейдж** (`BadgeMode`, страница настроек): «Видео на сегодня» (по умолчанию), «Все видео в очереди», «Убранные группы»; подсказка значка всегда полная: «На сегодня: 3 видео · 47 мин», «В очереди: …», «Убрано в TabFlow: 2 группы». Смена настройки → `storage.onChanged` → `background.refreshUi()`. Это и есть «дайджест»: всплывающих окон и уведомлений нет.
- В тестах: `t.report(tabId, report)` — отчёт content script; `t.api.videoPage` — страница, отвечающая на запрос отчёта; `t.settings.mode` + `t.bg.refreshUi()` — режим бейджа.

## «Рядом» — разделённый экран

Главная превращается в «смотрелку»: 2–9 сайтов рядом, каждый в своей рамке (iframe). Раскладка — `src/lib/tiling/layout.ts` (`tileRects`, `paneRects` — проценты); маршруты `#/side/<id>,<id>` и `#/layout/<id>` — `lib/app/route.ts`; панели и диалог — `lib/app/tile-picker.ts` (`pickedItems`, `layoutPanes`, `pickerGroups`, `openPages`); UI — `app/components/SideBySideView.tsx` (смотрелка) и `TileDialog.tsx` (выбор ссылок, сохранённые раскладки); команда `sleepLinks` — `background/group-actions.ts`.

- **Рамки, а не окна и не вкладки** (решение автора; окна Chrome и встроенный split view `tabs.createSplit` — только 2 вкладки — отвергнуты). Начальная раскладка по числу панелей (до 9, `MAX_TILES`): 2 — две колонки, 3 — первая слева на всю высоту + две справа стопкой, 4 — 2×2, 5 — 3 сверху + 2 снизу, 6 — 3×2, 7 — 4 + 3, 8 — 4×2, 9 — 3×3 (`ROWS` в `layout.ts`, по строкам), 1 (после закрытия панелей) — на весь экран; порядок = порядок выбора.
- **Запрет встраивания:** многие сайты присылают `X-Frame-Options` / `CSP frame-ancestors`. `allowFramesInThisTab` (`browser-api.ts`) ставит session-правило `declarativeNetRequest` (`declarativeNetRequestWithHostAccess`, без предупреждения при установке): убрать эти заголовки у `sub_frame` **только во вкладке главной** (`tabIds`, id правила = id вкладки) и только на сайтах с доступом. Некоторые сайты отказывают уже запросу рамки по `Sec-Fetch-Dest: iframe` (WhatsApp Web — 400; с `document` — 200) — правило заодно ставит `sec-fetch-dest: document`. Проверено в Chrome: WhatsApp Web в рамке открывается. Правило живёт, пока жива вкладка (других рамок на главной нет); правила закрытых вкладок чистятся при следующем открытии; после перезапуска Chrome session-правил нет.
- **Доступ к сайтам** — по сайту, как у очереди видео: «Открыть рядом» и клик по раскладке сначала вызывают `requestSiteAccess` прямо в клике (Chrome спрашивает только новые сайты). Отказали — в панели «Нет доступа к сайту … — Разрешить доступ / Открыть во вкладке». С доступом cookies в рамках страницы расширения не блокируются и хранилище не разделено — вход в аккаунт обычно сохраняется (документация Chrome «Storage and cookies»).
- **Доступ — ко всему сайту с поддоменами** (`sitePattern` → `*://*.tradingview.com/*`, `siteDomain` — регистрируемый домен: `co.uk`/`com.ru`-подобные и хостинги вроде `github.io` учтены вручную, без списка публичных суффиксов; IP и `localhost` — как есть). Причина — TradingView в рамке: запросы к `notifications.` и `pushstream.tradingview.com` шли без cookies входа (SameSite) → 403 и обрыв WebSocket. Одно правило и для очереди видео, и для «Рядом». Ранее выданный доступ к одному адресу `missingPatterns` считает неполным — Chrome спросит весь сайт при следующем открытии (у очереди — только у видео без длительности).
- **Что выбирается:** ссылки групп TabFlow и **открытые вкладки вне групп** (раздел «Открытые вкладки · вне групп» в диалоге; `listOpenTabs` + `openPages`: только `http`/`https`, без заглушек, одна вкладка на адрес; вкладки нативных групп — это группы TabFlow, они в списке групп). Ключ пункта — id ссылки или `u:<адрес>` (id вкладки меняется при выгрузке, адрес — нет); в `#/side/…` ключи закодированы, заголовок открытой вкладки смотрелка берёт у открытой вкладки с тем же адресом, иначе — домен.
- **Вкладки не трогаются**, кроме одного: вкладки показанных ссылок и выбранные открытые вкладки **засыпают** (`sleepLinks` с `tabIds` и `chromeTabIds`: `discardTab`; показанная в окне вкладка остаётся; новый id выгруженной вкладки ссылки записывается в ссылку; группа уснёт по зеркалу, если выгружены все). Без Undo — как «Усыпить».
- **Панель:** «Обновить», «Открыть во вкладке» (`openTab` для ссылки; `showOrOpenPage` — открытая вкладка с этим адресом или новая — для открытых вкладок и удалённых ссылок), «Закрыть панель» (только вид; ссылка в группе). Файлы и служебные адреса — только во вкладке. «К группам» возвращает на экран, откуда открыли (`viewerReturn` в store).
- **Свободные рамки:** сетка — только начальное положение. Рамка двигается за заголовок и меняет размер за любой край или угол (8 ручек в зазоре вокруг рамки), рамки могут перекрываться, тронутая последней — сверху (`zIndex`, DOM не переставляется — иначе рамки перезагрузятся). Положение — в процентах области (`moveRect`, `resizeRect`: рамка целиком внутри, не меньше 240×160 px). Первое касание фиксирует все рамки на местах — закрытие одной больше не перестраивает остальные. Пока тянут, рамкам `pointer-events: none` — иначе iframe перехватит указатель. «Выровнять» возвращает сетку.
- **Сохранённые раскладки** (таблица `layouts`, версия схемы 2): пункты в порядке панелей + копия адреса и заголовка — удалённая ссылка и открытая вкладка (без `tabId`) открываются по адресу; `rects` — где рамки (по одной на пункт, проверка `isPaneArrangement`, без индекса), нет — сетка. Пишет сама страница: галочка «Сохранить раскладку» в диалоге или кнопка в смотрелке (с текущим положением рамок, затем смотрелка показывает сохранённую раскладку), переименовать, удалить с «Отменить»; у открытой раскладки положение рамок сохраняется само после каждого перемещения (`setRects`), «Выровнять» его сбрасывает. Смотрелка перемонтируется при смене раскладки (`key={routeHash(route)}`), но у `#/side/…` ключ постоянный — добавление рамок не перезагружает открытые.
- **«Добавить»** (кнопка справа в шапке смотрелки, `AddPanesDialog` — тот же `TilePicker` в режиме `adding`): уже показанные адреса не предлагаются, номера продолжают текущие, выбрать можно сколько осталось до 9 (`togglePick(…, limit)`). Доступ к сайтам — в клике, вкладки выбранных засыпают. «Рядом» — новые ключи в конец маршрута (`withAdded`: закрытые рамки уходят из маршрута, чтобы не занимать место); сохранённая раскладка — ссылки дописываются в неё (`layouts.addLinks`: без повторов адресов, до 9; у передвинутых рамок места сохраняются, новые встают на места сетки нового числа). Новые рамки — сверху; пока рамки не трогали, сетка пересчитывается на новое число.
- Не проверено в Chrome: какие сайты всё равно не показываются в рамке (вход Google / OAuth, банки, проверка «меня встроили»), сохраняется ли вход на нужных сайтах.

## Настройки, резервная копия, e2e, магазин (этап 7)

Копия — `src/lib/backup/`: `format.ts` (формат, `parseBackup` / `readBackup`, `summarizeBackup`, `backupFileName`) · `export.ts` (`createBackup`) · `import.ts` (`importBackup`, `removeImported`). Команды — `background/backup-actions.ts` (`importBackup`, `undoImport`). Страница — `app/components/SettingsView.tsx`, чистая логика — `lib/app/settings-view.ts`. E2E — `e2e/` (`fixtures.ts`, `tabflow.e2e.ts`, `site.mjs`) и `playwright.config.ts`. Магазин — `store/`, `public/_locales/`, `scripts/icons.mjs`.

- **Резервная копия** (решение автора: только своя копия, без OneTab / Toby) — файл `tabflow-2026-10-19.json` (`format: 'tabflow-backup'`, `version: 1`): живые пространства, группы, ссылки, очередь (и «Просмотрено»), раскладки «Рядом», настройки. Корзины и связей с Chrome (`chromeGroupId`, `windowId`, `chromeTabId`, `playerOrigins`) в копии нет. Экспорт делает страница сама (`Blob` + `a[download]`, разрешение `downloads` не нужно).
- **Чтение файла** — поле за полем: лишнее отбрасывается, неподходящая запись пропускается, а не роняет весь файл; ссылки и видео — только `http`, `https`, `file`; ссылка без своей группы пропускается. Ошибки (`BackupError`): `not-json`, `not-backup`, `newer-version` — «Данные TabFlow не изменились». Background проверяет копию ещё раз (`readBackup` → `invalid-backup`).
- **Импорт** — командой (в очереди background, бейдж пересчитывается). Пустой TabFlow — сразу; иначе **каждый раз спрашивает** (решение автора). «Добавить» ничего не меняет и не удаляет: группы приходят **убранными** в конец своего пространства («Входящие» → «Входящие», остальные — к живому пространству с тем же названием без учёта регистра и «ё», иначе создаётся); группа и видео с уже занятым id (живые или в корзине) пропускаются, видео с тем же `videoKey` тоже, раскладки — по id; ссылка с занятым id получает новый, раскладка идёт за ним. «Заменить» — сначала всё в корзину, как удалением (`deleteSpace`, `deleteGroup` для «Входящих», очередь — `queue.remove`; открытые группы сохраняются, потом закрываются), затем копия с **новыми id** для занятых (`renewTakenIds`: старые записи теперь в корзине) и её настройки; раскладки «Рядом» не трогаются (корзины у них нет). Добавление — одна транзакция Dexie.
- **Undo** импорта — `undoImport`: добавленное удаляется насовсем (`removeImported`; группа, которую уже вернули на панель, остаётся; пространство — только пустое), заменённое возвращается из корзины, закрытые «Заменить» группы снова открываются.
- **Страница настроек** `#/settings` (маршрут в `route.ts`; `options_ui` = `options.html`, которая лишь переходит на `/app.html#/settings`; шестерёнка в popup — `runtime.openOptionsPage`): «Возврат групп», «Число на значке», «Сочетания клавиш» (`commands.getAll`, перечитываются при возврате фокуса; «Изменить в Chrome» → `chrome://extensions/shortcuts`), «Доступ к сайтам» (`permissions.getAll`, «Убрать доступ» → `permissions.remove`; если Chrome отказал — подсказка про `chrome://extensions`), «Данные» (экспорт / импорт), «Корзина», «О TabFlow» (версия, данные не покидают браузер).
- **E2E** (решение автора): `@playwright/test` + Chromium Playwright, `launchPersistentContext` с `--load-extension`, свежий профиль на тест, `workers: 1`. Сценарии: «Свернуть всё» → «Вернуть»; очередь в боковой панели и бейдж; настройки (`options.html` → `#/settings`, сочетания, смена бейджа); экспорт → импорт («Заменить», «Отменить», «Добавить»); файл не копии. Chrome-API из теста — `page.evaluate` на странице расширения (`globalThis.chrome`, тип — `typeof browser` из WXT). Второй параметр фикстур назван `provide`, а не `use` — иначе ESLint принимает его за хук React. Файлы — `*.e2e.ts` (Vitest берёт `*.test.ts` / `*.spec.ts`). В `getByRole` — `exact: true` для «Вернуть» («Свернуть всё» тоже подходит).
- **Бейдж после команды на старте** (найдено e2e): обновление бейджа, поставленное в очередь стартом, «покрывало» и следующую команду, но выполнялось до неё — значок оставался пустым. Теперь обновление, за которым в очереди есть работа, переставляет себя в её конец (`pendingWork` в `background/index.ts`), а `SerialQueue.idle()` ждёт, пока очередь не опустеет.
- **Магазин** (решение автора: витрина RU + EN): версия — `package.json` (1.0.0); название, описание и описания сочетаний клавиш в манифесте — `__MSG_…__` из `public/_locales/{ru,en}` (`extName`, `extDescription`, `cmd*`), `default_locale: 'ru'`; Chrome показывает их на языке браузера, а не по настройке TabFlow. Иконки 16/32/48/128 рисует `pnpm icons` (SDF с выборкой 4×4, PNG через zlib, без зависимостей; у 128 — 8 px поля). `store/`: `listing.ru.md` / `listing.en.md`, `privacy-policy.md` (RU + EN), `permissions.md` (единственная цель, обоснование каждого разрешения, анкета данных), `README.md` (чек-лист публикации; скриншоты 1280×800 и промо 440×280 — вручную).

## Автосон и «Порядок» (дубликаты, раскладка)

Чистая логика — `src/lib/tidy/`: `auto-sleep.ts` (`autoSleepTargets`, `parseSiteList`) · `duplicates.ts` (`findDuplicates`) · `grouping.ts` (`planGrouping`, `topicPlacer` / `sitePlacer`, `parseTopicRules`) · `topics.ts` (словарь тем) · `ai-grouping.ts` (запрос и ответ Gemini Nano). Background — `background/auto-sleep.ts`, `background/tidy-actions.ts` (`closeDuplicates`, `undoCloseDuplicates`, `groupTabs`, `undoGroupTabs`). UI — `app/components/TidyView.tsx` (экран `#/tidy`), `TidySettings.tsx` (разделы настроек), `SettingsParts.tsx` (`Section`, `ChoiceList`).

- **Одно правило совпадения адресов** — `urlKey` (`tab-rules.ts`, заменил `normalizeUrl`): без `#якоря`, меток рекламы (`utm_*`, `fbclid`, `gclid`, `yclid`, `ysclid`…), `www.`, `http`/`https`, `/` в конце и порядка параметров; YouTube — по id ролика при любом таймкоде. Им же пользуются «Убрать», «Сохранить ссылку», зеркало (`findMatch`) и поиск дубликатов.
- **Автосон** (решение автора: вкл., 30 мин; настройка 15 / 30 / 60 / 120 мин / выкл.): будильник `chrome.alarms` раз в минуту (`ensureAlarm` создаёт его, только если его нет, — иначе частые пробуждения service worker сбрасывали бы отсчёт). Неактивность — по `lastAccessed` вкладок Chrome (121+) и `createdAt` / `stateChangedAt` группы (только что разбуженная или созданная не засыпает сразу); в памяти ничего не держится. Не трогаются: группа активной вкладки любого окна, группа с «Не засыпать автоматически» (`TabGroup.keepAwake`, меню плитки, входит в копию), убранные и спящие. Исключённые вкладки (звук, закреплённые, `autoDiscardable: false`, ещё не `committed`, сайты списка «Не усыплять», служебные) остаются загруженными, **остальные вкладки их группы засыпают** (решение автора) — группа тогда остаётся «активной». Уснувшая целиком — `TabGroup.autoSlept` → «Уснула сама N назад» на плитке; `groups.setState` его сбрасывает. Группа на панели не сворачивается, тостов и бейджа нет.
- **Дубликаты** (решение автора: открытые вкладки + ссылки групп): открытые вкладки всех окон — остаётся вкладка на экране, потом закреплённая, потом вкладка группы TabFlow, потом с бо́льшим таймкодом YouTube, потом использованная последней; вкладки на экране и закреплённые не закрываются никогда. Ссылки — одинаковые в разных (и одной) группах: остаётся ссылка с открытой вкладкой, иначе самая старая; ссылки с открытой вкладкой здесь не удаляются. Наборы имеют ключ `tab:<urlKey>` / `link:<urlKey>`: страница показывает предпросмотр, команда передаёт выбранные ключи, background **ищет наборы заново** — устаревший предпросмотр не закроет не то. Ссылки уходят в корзину через `deleteTab` (БД, потом вкладка; последняя ссылка уносит группу), вкладки вне групп закрываются после. Undo: ссылки / группы из корзины в обратном порядке (группа на панели открывается снова), вкладки вне групп открываются на прежних местах.
- **Разложить вкладки** — вкладки текущего окна вне групп (не закреплённые, только сайты и файлы). По темам (решение автора: словарь без нейросети + Gemini Nano как эксперимент, выкл. по умолчанию): свои темы из настроек («Работа: jira, confluence, corp.example.com» — сайт с точкой или начало слова заголовка / часть домена) → словарь `topics.ts` (сначала самый длинный подходящий сайт, потом больше всего слов заголовка) → сайт. По сайтам — регистрируемый домен (`siteDomain`), файлы — «Файлы». Группа — от 2 вкладок; совпало название с группой этого окна на панели (без регистра и «ё») — вкладки встают в неё. Не больше 12 групп. Команда `groupTabs` перепроверяет каждую вкладку (вне групп, то же окно), создаёт нативную группу с названием и цветом и сразу `syncGroup` — зеркало кладёт её во «Входящие». Undo — `ungroupTabs` + `moveTab` на прежние индексы: распущенную группу зеркало забывает.
- **Gemini Nano** (`LanguageModel`, Prompt API; обёртки `builtInAiState`, `prepareBuiltInAi`, `promptBuiltInAi` в `browser-api.ts`): к расширению +0 МБ — модель качает и хранит Chrome (22 ГБ свободно, GPU 4+ ГБ или 16 ГБ ОЗУ). Русский официально не поддерживается: язык запроса — язык интерфейса, если `availability` его принимает, иначе `en`. Модель лишь называет темы и раскладывает номера вкладок (JSON-схема `AI_ANSWER_SCHEMA`, не больше 60 вкладок); непонятный ответ отбрасывается, пропущенные вкладки — по словарю. Скачивание модели — галочкой в настройках (прямо в клике). Свою модель (transformers.js, ~120 МБ) автор отклонил из-за размера.
- **Где в интерфейсе:** экран «Порядок» (`#/tidy`, сайдбар над «Корзиной»), popup — «Закрыть дубликаты · N» и «Разложить вкладки по группам · N» (открывают «Порядок» командой `openApp` с `screen: 'tidy'`; уже открытая главная переходит туда `navigateTab`), палитра Ctrl+K — те же два действия, настройки — «Автосон групп» и «Разложить вкладки». Настройки — `storage.local` (`tabflow.autoSleepMinutes`, `tabflow.keepAwakeSites`, `tabflow.groupingMode`, `tabflow.groupingRules`, `tabflow.aiGrouping`), в резервную копию пока не входят.
- В тестах: `FakeTabsApi.clock` (`lastAccessed` при создании и активации), поля `audible`, `autoDiscardable`, `lastAccessed` у `addTab`; `t.settings.sleep`, `t.bg.autoSleep()`.
- Не проверено в Chrome: будильник после сна service worker, `lastAccessed` после перезапуска Chrome, Gemini Nano на живой модели.

## Разбор, заметки, избранное, защита, «Поделиться»

Решения автора — `brand-identity/feature-ideas.md` («Выбрано»). Логика — `src/lib/app/review.ts` (`reviewItems`, `REVIEW_DAYS`), `src/lib/app/share.ts` (`linksText`, `markdownText`), `db/order.ts` (`byFavoriteThenOrder`, `indexInBlock`); UI — `app/components/ReviewView.tsx` (экран `#/review` и раздел настроек), `app/use-review.ts`, `GroupMenu`, `GroupTile`, `GroupDialogs`. Новые поля без индекса (версия схемы не менялась), все входят в резервную копию: `TabGroup.favorite`, `locked`, `reviewedAt`, `SavedTab.note`, `QueueItem.reviewedAt` (`TabGroup.note` был и раньше). Новых разрешений нет.

- **«Давно не открывали»** (отдельный экран; пункт сайдбара над «Порядком» со счётчиком; палитра Ctrl+K): убранные группы старше N дней (по `stateChangedAt`) и видео очереди старше N дней (по `createdAt`); N — 7 / 14 (по умолчанию) / 30 / выкл. в настройках (`tabflow.reviewDays`, в копию не входит). По одной карточке, самая старая первой: группа — «Вернуть на панель / Удалить / Оставить», видео — «Открыть / Наверх очереди / Удалить / Оставить». «Оставить» (и «Открыть», «Наверх») пишет `reviewedAt` — отсчёт заново, `updatedAt` не меняется. Удаление — командами, с «Отменить».
- **Заметки:** у группы — поле в диалоге «Название, цвет, заметка» (≤ 1000 знаков), одна строка на плитке (`fg-subtle`, обрезается, целиком — в подсказке); у ссылки — «Добавить заметку» в меню «⋯» ссылки, правка на месте (Enter / Esc), вторая строка под ссылкой (≤ 500). Пишет сама страница (только БД). Поиск: поле `note` в MiniSearch — и на главной, и в палитре.
- **Избранное** (галочка «В избранном» в меню плитки, звезда на плитке, чип «Избранное · N»): группа всегда первая в своём пространстве и на панели Chrome. Порядок держат сами ключи `order`: `groups.setFavorite` ставит группу в конец избранных / в начало остальных, `groups.place` и `move` не выводят её из своего блока (`indexInBlock`); `listBySpace` и обзор сортируют `byFavoriteThenOrder` — страховка для записей из импорта и корзины, следующее перемещение перепишет ключи. `followStrip`: группа, перетащенная на панели через границу избранных, двигается только внутри своего блока, а панель выравнивается снова (`arrangeGroups`).
- **Защита от удаления** (галочка «Защитить от удаления», замок на плитке): `deleteGroup`, `deleteTab` и перенос последней ссылки (`moveTab`) → `group-locked`; `deleteSpace` с защищённой группой → `space-has-locked`; «Удалить» в меню неактивно. «Свернуть всё» оставляет защищённую группу на панели (`CommandResult.kept` → «Защищённые от удаления остались на панели: 1 группа»). «Закрыть дубликаты» не трогает её вкладки и ссылки. «Убрать» и «Усыпить» работают — ничего не теряется. **Закрытие в Chrome — как обычно** (решение автора): закрыли группу — убирается, закрыли вкладку — ссылка в корзину. «Заменить» при импорте удаляет и защищённые (`ignoreLock`; «Отменить» возвращает всё). «Убрать выделенные» защиту не проверяет.
- **Поделиться** (подменю «⋯ → Поделиться ▸»): «Копировать ссылки» — адреса по одному на строку; «Копировать как Markdown» — `## Название`, заметка группы, строки `- [Заголовок](адрес) — заметка` (квадратные скобки в заголовке, пробелы и скобки в адресе экранируются). `navigator.clipboard.writeText` прямо в клике, без сервера; тост «Скопировано: 12 ссылок.»
- Не проверено в Chrome: буфер обмена из меню Radix (фокус документа), перетаскивание на панели через границу избранных (`onMoved`).

## Данные (этап 1)

`src/lib/db/`: `models.ts` (типы) · `db.ts` (схема Dexie, версии) · `order.ts` (ключи сортировки для drag & drop) · `repositories/` (spaces, groups, tabs, queue, trash) · `index.ts` (`db`, `repositories`, `createRepositories(db, clock)` для тестов).

- ID — UUID-строки; время — epoch ms; порядок — поле `order` (новый ключ — середина между соседями).
- Корзина — пометка `deletedAt` в тех же таблицах. Каскад (пространство → группы → вкладки) получает **один и тот же** `deletedAt`, восстановление возвращает только удалённое вместе. Через 30 дней — `trash.purgeExpired()`.
- **Зеркало:** в БД все группы, включая активные и спящие; связь с Chrome — `chromeGroupId` / `windowId` / `chromeTabId`, при `stowed` они очищаются. Восстановленная из корзины группа возвращается `stowed`, а если её пространство удалено — во «Входящие».
- Пространство по умолчанию «Входящие» (`spaces.ensureDefault()`) — его нельзя удалить; сюда попадает «свернуть всё».
- Очередь не добавляет дубликаты (тот же `videoKey`: id YouTube или URL без `#якоря` и позиции); приоритет = позиция по `order`. Поля `favIconUrl`, `playerOrigins` (этап 6) — без индекса, версия схемы не менялась.
- **Версия 2** — таблица `layouts` (сохранённые раскладки «Рядом»; входят в резервную копию).
- Ошибка «запись не найдена» — `RecordNotFoundError`. Не называть ошибки `NotFoundError`: Dexie внутри транзакций подменяет их своим классом с тем же именем.
- Схему менять только новым `this.version(N + 1)`, старые версии не редактировать.

Технические заметки:

- **Автоимпорты WXT выключены** (`imports: false`) — всё импортируется явно: `wxt/browser`, `wxt/utils/define-background` и т.п.
- **TypeScript закреплён на 6.0** — typescript-eslint пока не поддерживает TS 7.
- Шрифты — локально через `@fontsource` (только кириллица и латиница), без запросов в сеть.
- pnpm поставлен через `npm i -g pnpm` (`corepack enable` требует прав администратора).
- Chrome 155 игнорирует флаг `--load-extension`, поэтому `pnpm dev` не подгружает расширение в обычный Chrome — «Загрузить распакованное» вручную. E2E грузят его в **Chromium Playwright** (`channel: 'chromium'`, headless работает; браузер ставится `pnpm exec playwright install chromium`, ~150 МБ в `%LOCALAPPDATA%\ms-playwright`).
- Prettier не трогает `*.md`, `design/`, `brand-identity/`.
- **Вкладки и группы — только через `TabsApi`** (`lib/browser-api.ts`); в тестах — `FakeTabsApi` (`lib/testing/fake-tabs-api.ts`) и `setupBackground()` (`lib/testing/background.ts`). `fakeBrowser` из WXT не умеет `tabGroups`, `tabs.group`, `tabs.discard`. Фейк повторяет важное поведение Chrome — при изменении логики сверять с настоящим Chrome. `moveTab` в фейке: вкладка вне своей группы выходит из неё, между двумя вкладками группы — входит (как в Chrome; край группы — проверить вручную).
- Особенности Chrome 155, проверенные вручную: `tabs.discard` при отказе **не бросает ошибку, а возвращает `undefined`**; выгрузка **меняет id вкладки**; вкладка, выгруженная до фиксации адреса, становится `about:blank` — выгружать только после `committed` (поле `BrowserTab`).
- Хук ECC `config-protection` запрещает менять `eslint.config.js` — правила ослаблять нельзя, исправлять код (в тестах вместо `!` — типизированные кортежи).

## Ключевые продуктовые решения

1. **Группа — три состояния:** активна (на панели, загружена) · спит (на панели, `chrome.tabs.discard`) · убрана (только в TabFlow, вкладки закрыты, возвращается нативной группой Chrome с тем же цветом и названием).
2. **Обзор плитками как в YouTube:** карточка группы = превью 16:9 (мозаика 2×2 из вкладок; у YouTube — обложки по ID видео) + название + статус.
3. **Очередь видео с приоритетом** (в основном YouTube): длительность, прогресс, «на сегодня: N видео · M мин», подбор под свободное время. Живёт в **боковой панели** (`chrome.sidePanel`).
4. **На виду, но не в памяти:** спрятанный список забывается (как YouTube «Смотреть позже» и OneTab) — поэтому бейдж, боковая панель, дайджест при запуске браузера. Напоминания по ситуации, не по часам и не всплывающими окнами.
5. Закрывать вкладки только **после** успешной записи в БД. Service worker MV3 засыпает — состояние не держать в памяти.
